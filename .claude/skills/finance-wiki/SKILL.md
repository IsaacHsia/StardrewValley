# 财经 Wiki 系统

基于 Andrej Karpathy 的 LLM Wiki 理念构建的个人财经知识库系统。三层架构：Raw/ → Wiki/ → schema.md。

---

## 操作代号体系

| 代号 | 全称 | 操作 |
|------|------|------|
| `rw` | rewrite | 校对视频文字稿 → Raw/ |
| `ing` | ingest | 消化入 wiki |
| `qry` | query | **基于 wiki + 当前市场结构回答提问**（见下方 qry 方法论） |
| `chk` | check | wiki 体检 |
| `trk` | track | 标的追踪 |
| `sum` | summarize | 跨文章归纳 |
| `sug` | suggest | **交易策略建议**：持仓分析+大盘判断+开仓建议+仓位分配 |
| `scn` | screen | **尾盘筛选**：结合近两周复盘内容+当前盘面，筛选次日候选标的 |


## Query 操作（`qry`）—— 基于清枫框架 + 市场结构回答提问

用户问「明天买什么」「这个方向怎么样」时，**不能只复述清枫的话**。必须做四层筛选。

### qry 四步法

```
第一步：清枫当前主线是什么？
  → 从最近早盘/复盘中提取主线排序（如：光互连#1 > MLCC#2 > 存储#3）

第二步：主线内，谁涨了、谁没涨、谁回调到位了？
  → 拉取主线内标的的今日行情
  → 区分：高位（今天涨5%+）、低位（今天涨<2%或下跌）
  → 注意：板块内的高低位轮动（如光纤涨了→CPO交换机还没涨）

第三步：明天情绪预判 + 资金流向推演
  → 清枫说明天科技承压还是回暖？
  → 周四/周五？周一？（情绪周期规律：周一最强，周四~周五最弱）
  → 资金会从高位流向低位，还是继续推龙头？

第四步：筛选候选标的
  → 条件：主线内 + 位置低（今天没涨/回调）+ PE合理 + 主板/中小板 + 一手在预算内
  → 给用户候选清单，不是给一个方向
```

### qry 禁止事项

- ❌ 清枫说看好 X → 推荐买 X（跳过了市场结构分析）
- ❌ 只给方向不给具体标的
- ❌ 忽略周几的情绪周期规律
- ❌ 推荐创业板/科创板（用户买不了）
- ❌ 推荐一手超过用户预算的标的

## Screen 操作（`scn`）—— 尾盘筛选次日候选标的

触发条件：用户说 `scn`、`尾盘筛选`、`明天买什么`、`尾盘选股`。

### scn 五步法

```
第一步：提取近两周清枫提及的标的
  → 扫描最近 14 天的 Raw 早盘/复盘/午盘文件
  → 提取所有清枫点名的标的（含研报部分）
  → 标注每个标的所属方向（光互连/MLCC/存储/封测/PCB/Agent...）

第二步：获取当前盘面数据
  → 拉取候选标的的实时价格、涨跌幅、PE、换手
  → 拉取上证指数点位、成交额

第三步：标记位置状态
  → 🔴 高位：今日涨停 / 连续大涨 / 清枫说"高潮不追"
  → 🟢 低位：今日平盘或下跌 / 近期回调/ 清枫说"可以低吸"
  → 🟡 中间：今日小涨 / 方向对但不在最佳买点

第四步：结合情绪周期和明日预判
  → 今天是周几？（周三→周五尾盘加回，周一→正常操作）
  → 清枫说明天怎么看？（早盘承压/午盘回流/弱修复）
  → 资金明天会往哪里流？（高位→低位？旧→新？）

第五步：输出候选清单
  → 优先：清枫主线内 + 位置低 + PE合理 + 主板/中小板 + 一手在预算内
  → 标注每只标的的买入条件（什么价位、什么时间）
  → 标注每只标的的风险（为什么可能不涨）
```

### scn 输出格式

```
## 尾盘筛选 [日期]

### 大盘状态
上证 xxxx | 成交 x.xx万亿 | 情绪：xxx

### 明日预判
[清枫的定调 + 周几规律]

### 候选标的

| 优先级 | 标的 | 方向 | 现价 | 一手 | PE | 今日 | 买入条件 | 风险 |
|--------|------|------|------|------|-----|------|---------|------|
| #1 | xxx | xxx | xx | xxxx | xx | +x% | 回落到xx买 | xxx |

### 今日不追
[涨停的、高位、明天可能回调的]

### 持仓对照
[你现在的持仓在候选方向中的位置]
```

### scn vs qry 的区别

| | qry | scn |
|------|-----|------|
| 触发 | 用户随时提问 | 尾盘 14:00~14:30 |
| 重点 | 回答具体问题 | 系统扫描+输出候选清单 |
| 输出 | 针对性回答 | 标准化表格 |
| 频率 | 不限 | 每天一次 |

## Ingest 操作（`ing`）

主 agent 直接处理。逐篇优于批量。

单篇步骤：
1. 对照 log.md 确认未处理 Raw 文件
2. 阅读全文（强制确认覆盖到文件末尾）
3. 提取关键信息
4. 写入 Wiki
5. 写入后抽查末尾 3 段是否完整
6. 自进化检查 + 时效性检查
7. 更新 index.md、log.md

II 类文件（午盘补发/周末补充/晚间复盘）逐段对比 Wiki 页，不遗漏追加内容。

## Suggest 操作（`sug`）—— 交易策略建议

触发条件：用户说 `sug`、`开仓`、`买什么`、`持仓分析`、`交易策略`。

执行流程：
1. 运行 `scripts/coarse_screen.py` 和 `scripts/fine_screen.py` 获取最新数据
2. 阅读最近 2-3 天的博主早盘/复盘/午盘补发 Raw 文件
3. 阅读 `Wiki/博主/博主决策时间线.md` 了解博主最新节奏
4. 阅读 `Wiki/数据/博主标的池日报.md` 获取布林线信号
5. 严格按 `trade_template.md` 格式输出

### 回复规则

**"不能"**：博主说减仓/不追高/等冰点且冰点未到；标的池全部在布林线一轨以上；退潮期

**"建议开"**：博主说分歧加仓/冰点低吸且冰点已现；有非科创板标的触发收敛/N字二轨信号

**"能"**：博主说持股为主/可以开仓/上升趋势完好；有二轨附近标的且优先级前 3

**其他 → "不建议"**

### 标的筛选规则
- **科创板（688xxx）自动排除**，用户买不了
- ETF 仅在博主明确提及时纳入，不自己编
- 优先推荐非科创板 + PE 在同板块中偏低 + 布林线收敛或二轨附近 + 博主优先级前 3 的标的

## 时效性管理

短线 5d → 🟡 | 趋势 30d → 🟡 | 产业逻辑 90d → 归档 | 方法论 → 永久。

标的总览三层：🟢 近期活跃 / 📁 历史归档 / 📖 案例股。

## 赛博 UP 主分析能力

### 持仓诊断流程
grep 全踪迹 → 定位框架 → 保鲜期 → 博主框架判断 → 区分博主/自己判断 → 问成本/仓位

### 矛盾检测
拉态度时间线 → 标 🟢🟡🔴 → 查数据支撑 → 标沉默风险

### 博主框架速查表
能不能做 > 怎么做 > 做什么 | 80%贝塔+20%阿尔法 | 产业逻辑标的逻辑破坏才走 | 短线止损是纪律 | 不同周期不混用 | 风控第一

## 关键经验

1. 不做 RAG，做 wiki
2. 逐篇优于批量
3. ingest 必须读到 Raw 末尾，写入后抽查
4. 主 agent 直接处理 ingest
5. 时效性分层
6. sug 回复严格按模板，不自由发挥
7. 科创板不推荐
8. 诚实 > 讨好
