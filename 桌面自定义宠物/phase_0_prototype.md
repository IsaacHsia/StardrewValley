# 阶段 0：原型验证

## 1. 阶段目标

验证桌面宠物的核心技术可行性。

本阶段不追求完整商业品质，也不要求最终美术效果，重点是证明以下体验可以跑通：

- 宠物可以显示在电脑桌面上
- 宠物窗口支持透明背景
- 宠物可以置顶显示
- 宠物可以响应鼠标和键盘操作
- 宠物可以播放基础动作

## 2. 玩家体验目标

玩家打开 Demo 后，可以在桌面上看到一只默认宠物。宠物会自动待机、走动、睡觉，玩家点击或拖拽宠物时有反馈，玩家打字时宠物会产生简单反应。

## 3. 功能需求

### 3.1 桌面窗口

- 创建透明桌面窗口
- 支持无边框显示
- 支持窗口置顶
- 支持窗口拖拽
- 支持鼠标穿透开关
- 支持宠物显示在当前桌面坐标中

### 3.2 默认宠物显示

- 加载一只默认宠物素材
- 支持透明背景精灵
- 支持宠物缩放
- 支持宠物左右翻转
- 支持宠物在屏幕范围内移动

### 3.3 基础动作

本阶段至少需要以下动作：

- Idle：待机
- Walk：走动
- Sleep：睡觉
- Clicked：被点击
- Dragged：被拖拽
- TypingReact：玩家打字反应

### 3.4 输入响应

- 检测鼠标位置
- 检测鼠标点击宠物
- 检测鼠标拖拽宠物
- 检测键盘输入频率
- 检测玩家空闲时间

注意：键盘检测只记录输入频率，不记录具体按键内容。

## 4. 程序需求

程序交付内容：

- Windows 桌面透明窗口 Demo
- 默认宠物加载逻辑
- 基础动画播放逻辑
- 简单状态机
- 鼠标点击和拖拽逻辑
- 键盘输入频率监听
- 空闲时间检测
- 多显示器兼容性初步验证

建议模块：

- DesktopWindowController
- PetView
- PetAnimationController
- PetStateMachine
- InputActivityWatcher

## 5. 美术需求

美术交付内容：

- 默认猫宠物测试素材
- 3 到 5 个基础动作
- 动作帧图或序列帧
- 透明背景素材
- 简单测试用 UI 图标，可选

动作建议：

- 待机：轻微呼吸或眨眼
- 走动：左右移动循环
- 睡觉：趴下或闭眼
- 点击：抬头、惊讶或摇晃
- 拖拽：被拎起或悬空状态

## 6. 验收标准

本阶段完成标准：

- 启动程序后，桌面出现一只宠物
- 宠物背景透明
- 宠物可以播放待机、走动、睡觉动作
- 鼠标点击宠物时有反馈
- 鼠标拖拽宠物时宠物跟随移动
- 玩家持续打字时，宠物触发打字反应
- 玩家一段时间无操作时，宠物进入睡觉或待机状态

## 7. 阶段风险

主要风险：

- 透明桌面窗口在不同 Windows 系统上的兼容性
- 鼠标穿透与拖拽逻辑冲突
- 键盘监听可能触发杀毒软件或隐私疑虑
- Godot 桌面透明窗口能力需要提前验证
- Steam 运行环境下的窗口置顶行为需要验证
