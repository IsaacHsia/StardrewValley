# AI 使用反模式与成本优化

> **来源系列：** AI 使用反模式视频教学（7 集）
> **摄取日期：** 2026-07-07
> **核心主题：** 从「会用 AI」到「用好 AI」——识别六大反模式，建立工程化 AI 使用习惯

---

## 总览

本系列以「AI 使用反模式」为线索，揭示了从个人开发者到团队在 AI 工具使用中最常见的六大错误习惯。这些反模式并非技术能力问题，而是**认知与习惯问题**——大多数用户在不自觉中浪费了 50-80% 的 token 预算，同时获取了更差的结果。

核心洞察：**AI 不是越贵越聪明，也不是越自动越好。正确范围 + 正确模式 + 正确习惯 = 中等模型也够用。**

---

## 六大反模式与对应解法

### 🔴 反模式一：无脑顶配 → 模型不分级

**症状：** 翻译/润色/改路径也用最强模型 + 全量上下文 + max thinking。

**案例：** 包体构建失败，丢整份项目说明 + 所有日志 + 两周提交记录给最贵模型，花 2000+ token 定位问题，同事 5 秒找到（特效图改名没同步）。

**根源：** 「越贵越聪明」的错觉——忽略了大部分 token 消耗在「筛垃圾」而非「解决问题」。

**解法：**
| 任务类型 | 推荐模型等级 |
|---------|------------|
| 翻译/润色/简单修改 | 便宜快速模型 |
| 写网页/改方案 | 中高阶模型 |
| 长链路推理/多文件重构 | 强模型 |
| 批量生图 | API（非个人积分） |

**原则：** 价格从几块到几百块/M 差百倍，但翻译一个词贵模型不会好百倍。

---

### 🔴 反模式二：上下文脏乱 → 一窗到底

**症状：** 对着一个窗口从需求聊到上线复盘，环境越来越脏；Tools/MCP/Skills 没用也在挤占上下文。

**案例：** 用户发了个"嗨"，上下文直接跳到 300K；AI 把春节活动规则套到夏日泳装卡池——不是换模型了，是 context 里老旧信息太多。

**根源：** 不理解上下文组成 = AI 能看到的所有资料包（聊天记录 + 打开文件 + 工具说明 + 系统规则 + Skills + MCP + 记忆信息）。

**关键数据：** 对话越长每轮越贵（每轮要看全部历史）；上下文满了不会自动扩容，AI 会粗暴压缩 → **降智**。

**解法：**
1. **拆任务：** 文案 → 数值 → 回归测试，分开做，各自开新窗口
2. **阶段总结：** 每完成一段让 AI 做阶段总结
3. **搬运摘要：** 下一阶段开新对话，搬运摘要过去
4. **工具分级管理：**
   - 系统级：长期稳定，全局生效
   - 用户级：个人常用，适度注入
   - 项目级：仅当前项目需要，用完即关
5. **不相关的问题直接新开窗口**

---

### 🔴 反模式三：Cache 盲区 → 预算失控

**症状：** 不知道 Cache 的存在，在长对话中频繁换模型、改 Rules、中途离开，导致 cache 反复失效。

**关键机制：**
- 相同内容短时间内重复遇到 → 平台复用计算结果，收费为正常 **1/10**
- 写入条件：内容 ≥ 1024 Token，写入价格贵 1.25 倍
- **窗口期约 5 分钟**

**失效三件套（多数人全中）：**
1. **中途打断** — 聊天记录在，cache 不在（5 分钟过期）
2. **对话中换模型** — 几百 K 上下文重新给新模型算一遍，写 cache 比正常还贵
3. **改 Rules/系统提示词措辞** — 哪怕"资深"改成"顶级"，cache 就没了

**最大化命中的四个习惯：**
1. ✅ 稳定前传放前面（项目背景、代码规则），本次问题放后面
2. ✅ 相同背景的关联问题集中连续问（5 分钟内）
3. ✅ Rules 定好就别改措辞
4. ✅ 不相关的问题直接新开窗口

---

### 🔴 反模式四：Prompt 随心所欲 → 信息密度为零

**症状：** 懒得写清楚、客气话连篇、带情绪、思维跳动、不设边界、啰嗦、截图当万能药。

**Prompt 的七个常见错误：**
1. **懒** — "帮我优化一下这个模型问题"（没说清是贴图还是拓扑）
2. **客气** — "麻烦你有空帮我看一下这个可能有一点点问题的小东西"（对 AI 没用，纯耗 token）
3. **情绪** — "你个笨蛋怎么又改错了"（导致 AI 矫枉过正）
4. **思维跳动** — 前面聊 3D 模型，突然问"推荐晚饭"
5. **不设边界** — 不说"只提修改意见别直接改文件"
6. **啰嗦** — 以为写得长等于写得好
7. **截图/文件当万能药** — "反正文件在那儿它自己应该能看懂"

**正确 Prompt 公式：**
```
我是 [角色]，正在 [任务]，[具体问题]。[限制条件]。[期望的输出形式]
```

> 例：我是 3D 美术，正在修角色肩部 LOD，问题是远景边缘硬折太明显。只允许修改 LOD 模型的肩部网格，不改设计。请先给修改意见，不要直接改文件。

**核心原则：** 好的 prompt 无关长短和情绪，核心是**精准的信息密度**。

---

### 🔴 反模式五：黑盒抽卡 → 没有工程化流程

**症状：** 一条指令让 AI 全流程自动完成，结果错了不知在哪错，反复抽卡等运气好的一版。

**案例：** 做运营周报，一条指令全流程（数据抓取 → 表格清洗 → 制图 → 拼接 → 导出 PDF），PDF 吐出来但图表数值对不上，重做十次总有一版"看起来还行"——还把整串对话封成 Skill（灾难放大器）。

**问题本质：**
- 把完整流水线塞给大模型硬跑，中间不可控
- 错了不知道是数据错、图表错还是导出错
- 反复抽卡 = 同样的问题花十份钱等一次运气

**正确工程化思路：**
| 步骤 | 谁来执行 |
|------|---------|
| 发数据 | 固定脚本 |
| 表格清洗 | 代码 |
| 制图 | 可复现脚本/插件 |
| 判断/规划/创意/补代码 | AI |
| 改错误 | 人工 + AI |

**核心：** 拆成能单独验收的步骤，哪步坏修哪步。AI 是高级员工，不是魔术黑箱。

---

### 🔴 反模式六：积分浪费 → 用个人积分干批量活

**症状：** 用 Cursor/Claude 个人积分批量生图、跑定时任务，一周烧完一个月预算。

**成本对比（同参数下）：**
| 方式 | 成本 |
|-----|------|
| 个人积分（$4.6 模型） | 平均一张 ~13.7 积分 |
| Team AI API | 平均一张 ~3.73 积分（**成本 1/4**） |

**解法：**
- 批量生图/定时任务 → **用 API 替代个人积分**
- 前期探索用低分辨率，确定方向再上高质量参数
- 不懂 API？把调用示例丢给 AI 帮你写代码
- 避免无意义下载大量 Skills（每次触发指令跑一堆陪跑 Skills）

## 核心知识体系总表

### 概念辨析：Skills ≠ Rules ≠ MCP ≠ Memory

| 概念 | 作用 | 加载方式 | Token 消耗 |
|------|------|----------|-----------|
| **Skills** | 专项任务执行链路文档 | 触发时加载 | 按需 |
| **Rules** | 全局行为准则 | 每轮注入 | 常驻 |
| **MCP** | 调用外部工具协议 | 配置即注入 | 常驻（无论是否调用）|
| **Memory** | 长期记忆 | 每轮注入 | 常驻 |

### 模式选择金字塔

| 模式 | 适用场景 | Token 消耗 | 使用建议 |
|-----|---------|-----------|---------|
| **Ask** | 解释、咨询、简单问答 | 最低 | 仅提问不执行时用 |
| **Plan** | 先规划再执行的任务 | 中等 | 复杂任务首选 |
| **Agent** | 直接执行、频繁文件操作 | 高 | 事前确认验收标准 |
| **Multi-task** | 并行多子任务 | 最高 | 慎用，各自独立上下文 |

**原则：** 提问前想好要什么反馈形式——勤切换模式比一直用最高模式更省钱。

## 最佳实践 Checklist

### 每日习惯
- [ ] 新任务开新窗口（不要一窗到底）
- [ ] 写 prompt 用公式：角色 + 任务 + 问题 + 限制 + 期望
- [ ] 任务开始前评估：这需要 Ask / Plan / Agent？
- [ ] 稳定上下文（Rules 不改措辞）
- [ ] 相关任务集中 5 分钟内连续完成（利用 cache）

### 每周习惯
- [ ] 检查 Token 消耗面板（了解哪里花得多）
- [ ] 评估 Skills 使用率，关闭无用 Skills
- [ ] 为高频重复任务写固定脚本（替代 AI 全流程）
- [ ] 考虑哪些批量任务可迁移到 API

### 成本控制
- [ ] 模型分级：简单任务用便宜模型
- [ ] 不用个人积分做批量/定时任务
- [ ] 理解 cache 机制，配置稳定的系统提示词
- [ ] 翻译润色等轻量任务不喂全量上下文
